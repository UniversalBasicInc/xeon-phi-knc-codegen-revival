# Prior art found 2026-11-02 — the missing brick is already laid

`docs/UNIVERSAL-TRANSLATOR.md` said the one missing layer for KNC was an LLVM backend for
MVEX, and that nobody would lay it because the payoff for dead hardware is zero. That was
true in August. It is not true now. Two independent projects did it in September–October 2026.

## 1. Lasimeri — a whole stack, no MPSS

- **Intel-Phi-LLVM** (MIT; LLVM patches Apache-2.0 w/ LLVM exception; pushed 2026-10-17).
  LLVM 23.1.1 + clang with `-march=knc`. The complete KNC instruction table extracted from
  Intel manual 327364 (330 defs), MVEX encode/print/disassemble verified byte for byte
  against Intel's binutils 2.22 (6,708 of 6,708), 297 `llvm.x86.knc.*` intrinsics behind
  `<kncintrin.h>` with Intel's names. Stages S0–S3 done with measured results; S4 (Rust),
  S5 (native clang on the card), S6 (auto-vectorisation) open.
- **Intel-Phi-3120A** (pushed 2026-10-13). From-scratch Rust host daemon over VFIO: no host
  kernel module, no MPSS. The card boots **mainline Linux 7.2.3** with a 30-patch series on
  all 228 threads; dropbear ssh; native clang 22 on the card; persistent disk over the
  card's DMA engine; host RAM as swap; sensors, perf counters, `phitop`.
- **Intel-Phi-AVX512** (pushed 2026-10-14). Runs an unmodified host program's AVX-512 on
  the card from its SIGILL, and carries llama.cpp matrix multiplies beside the host.
- Their card is a 3120A (`8086:225d`). Ours is a 31S1 (`8086:225e`): same silicon family,
  different memory/TDP, so everything above needs re-verifying here — which is a
  contribution, not a duplication.

## 2. ShisoftResearch — xeon-phi-toolchain 0.2.0

- Apache-2.0 w/ LLVM exception; pushed 2026-10-28. LLVM/Clang for k1om (one 37k-line
  patch), **Rust nightly-2026-09-01 with `std::simd`** validated on the card (9,380 API
  cases), **C++17** via a GCC 13.4 libstdc++ build, native math runtime, capability matcher.
  Needs the MPSS 3.8.6 SDK sysroots (`sysroots/k1om-mpss-linux`), which we have.
- llama.cpp KNC kernels with measured numbers (one KNC, Q4_0, tokens/s): Qwen3.5-0.8B
  9.87 gen / 24.5 prompt; 4B 3.08 / 6.97; 9B 2.66 / 5.08. A KNL 7210 is ~3x faster.
  Interesting as a proof; irrelevant as a service at 270 W.

## 3. Intel's OpenCL 14.2 runtime survives

`archive.org/details/opencl_runtime_14.2_x64_setup` — the last runtime with Xeon Phi
support, 90 MB. Also `gnu_binutils_2_22_l1om` (the MVEX assembler) and `mpss-intel`
(3.9 GB collection). Mirrored to the EPYC host `/data/knc/{opencl,binutils}`.

## What this does to the plan

| Was | Now |
|---|---|
| Route 2: forward-port the MPSS driver to a modern kernel | Done elsewhere, and better: mainline kernel *on the card*, userspace VFIO daemon on the host. Reproduce, don't redo. |
| Route 3: an MVEX backend in LLVM, "the research project" | Exists twice. Not novel. The open items are theirs (S4–S6) and our SKU. |
| Scalar SYCL blocked on C++17 | Unblocked: ShisoftResearch ships C++17 for k1om. AdaptiveCpp library-only backend is now a build, not a toolchain fight. |
| Rust impossible on k1om | Rust std + portable SIMD validated on the card. |
| GROMACS 2016–2018 on the card via the k1om GCC | Still unclaimed by anyone. With clang-knc + C++17, GROMACS 2024+ may build natively. This is the one thing on this list nobody else has done. |

Honest read: a new compiler backend is no longer a contribution anyone needs from here. What
remains is worth more to this project anyway: a second-SKU reproduction with bug reports
upstream, GROMACS on a dead ISA, and the e-waste story. Both authors publish measured
results and decision records; contribute in that register.
